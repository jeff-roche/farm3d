# P5 OrcaSlicer Runtime Spike

Task 1 of `docs/superpowers/plans/2026-09-24-p5-runtime-slicing-slice-revisions.md`
(GitHub issue #15). It ran on 2026-09-24 on the Linux x86_64 development
host. It makes no claim about Windows or macOS.

## Decision

| Question | Decision | Evidence |
|---|---|---|
| Invocation shape (plan P4) | **Keep.** One process per plate. Input is a farm3d-authored core-only 3MF. The arguments are `--datadir <empty> --outputdir <out> --load-settings "machine;process" --load-filaments filament --arrange 0 --orient 0 --slice 1 [--pipe fifo]`. The Orca `model_settings.config` fallback is **not needed**. | Gates C, D |
| Presets (plan P3) | **Keep flat presets, with `from: "system"` and the original system preset names.** Overrides are applied to the flat JSON. farm3d must check filament compatibility itself. | Gate B, Gate F |
| Preset source for cache-only runtimes | **Option B (user decision):** a separate JSON-bearing preset source. The 2.5.0-dev nightly ships no JSON presets, and its CLI cannot resolve `inherits` from its own cache. | Gate B |
| Progress (plan P5) | **Keep the FIFO**, opened read-side non-blocking *before* spawning. There is no progress on non-Linux builds, as the source predicted. | Gate E |
| Cancel and orphans (plan P5) | **Keep the process group plus SIGTERM** (exits in 31 ms). **Add `PR_SET_PDEATHSIG(SIGTERM)`** on Linux. **Escalate to SIGKILL only after SIGTERM times out**, because SIGKILL of an AppImage leaves a stale FUSE mount. | Gate E |
| Time limit | **Change:** `--mstpp` is not enforced. farm3d needs its own wall-clock timeout. | Gate E |
| Output validation (plan P6) | **Keep, and make it stricter.** Require the `plate_1.gcode` file. `--slice N` for a plate that doesn't exist returns exit 0 and "Success." with no G-code. The exit code is `return_code mod 256`. | Gate F |
| Determinism (plan P6) | **Keep.** Only line 2 (`; generated by … on <date> at <time>`) varies, across runs *and* across work directories. No paths are embedded. | Gate G |
| Renderer (plan P9) | **Keep three.js**, with meshes sent as binary buffers. | Gate H |
| Flatpak | **Not run.** It would need a Flatpak install on the user's system. The Flatpak stays unsupported until it is tested. | Gate I |
| Installed package | **Scrub the environment anyway.** farm3d's own AppImage leaks `LD_LIBRARY_PATH`, `PATH`, `APPDIR`, `APPIMAGE`, `GDK_BACKEND=x11`, and `XDG_DATA_DIRS` into children. The v2.4.2 AppImage tolerated all of them, but the process layer builds an explicit environment rather than relying on that. | Gate J |

## Approval

The user approved this spike on 2026-09-24 and chose **option B** (separate
engine and preset source) for the open decision below.

## Open decision: where a cache-only runtime's presets come from (decided: B)

The user asked to allow 2.x **and nightlies** (plan P2). The spike shows
that current nightlies can't supply presets farm3d can read:

- **The profile layout changed.** Upstream commit "Cache system presets to
  eliminate startup and wizard load times (#14217)", from 2026-08-21, ships
  each vendor as a binary `<Vendor>.opc` (magic `ZCRO`, format version 1).
  It removes the JSON preset files from `resources/profiles/`. The design
  doc (`docs/HLSD/preset-cache.md` upstream) calls this the shipped form, so
  2.5.0 releases will probably be the same.
- **The nightly CLI cannot resolve `inherits` from the cache.**
  - A thin `from: "User"` preset that names only its parent fails with an
    empty `--datadir`: "Preset was not found in the loaded bundle".
  - It also fails with the nightly's `.opc` files copied into
    `datadir/system/`: the loader looks for `<Vendor>.json`.
  - It also fails with a copy of the user's own `~/.config/OrcaSlicer/system`.
    That copy has JSON for the installed vendors, but `OrcaFilamentLibrary`
    exists only as `.opc`.
- **Flat presets built from v2.4.2 work on the nightly.** The Elegoo
  Centauri Carbon cube sliced successfully. The output differs from
  v2.4.2's: the estimate is 5m 6s against 4m 33s, from engine changes.

**Options:**

- **A. JSON-bearing runtimes only.**
  - farm3d resolves presets from the runtime's own `resources/profiles`.
    Those are all 2.x releases through 2.4.2, and nightlies built before
    2026-08-21.
  - A cache-only runtime is detected. It is shown as "This OrcaSlicer build
    stores presets in a format farm3d can't read yet", and slicing is
    blocked.
  - Cheapest and fully consistent. But today's nightlies are blocked.
- **B. A separate preset source** *(recommended)*.
  - A runtime is an **engine** (any accepted 2.x, including nightlies) plus
    a **preset source**. The preset source is a JSON-bearing OrcaSlicer
    installation, and it defaults to the engine itself when that engine has
    JSON presets.
  - With a cache-only nightly, the user also points farm3d at a JSON-bearing
    installation, for example the v2.4.2 AppImage.
  - Every Slice Revision records both versions, and the review shows
    "presets from 2.4.2, engine 2.5.0-dev".
  - Nightlies work today. Presets can lag the engine: a new key falls back
    to the engine default, and a removed key is dropped, as with any config
    file.
- **C. A farm3d `.opc` reader.**
  - Port `PresetCacheFormat.cpp` (588 lines) and Orca's per-type binary
    value encodings.
  - It is exact for any runtime. But it is tied to an internal format that
    is a month old, and it breaks whenever `CACHE_VERSION` or a value
    encoding changes.

B builds on A: A's detection and resolver are needed either way. C could be
added later if upstream's format settles.

### Failure mapping (v2.4.2)

The exit status is `return_code` modulo 256, so −50 appears as 206.
`result.json` is always written on Linux.

| Case | Exit | `return_code` | `error_string` (truncated) | Outputs |
|---|---|---|---|---|
| Object partly outside the bed (the only object) | 206 | −50 | "One of the plate is empty or has no object fully inside it…" | none |
| Object fully outside the bed | 206 | −50 | same | none |
| Malformed process JSON | 251 | −5 | "The input preset file is invalid and can not be parsed." | none |
| Missing input 3MF | 253 | −3 | "The input files to the slicer are not found." | none |
| Missing preset file | 253 | −3 | same | none |
| Plate 3MF with an empty `<build>` | 250 | −6 | "The input model file to the slicer can not be parsed." | none |
| Process preset incompatible with the machine | 239 | −17 | "The selected printer is not compatible with the process preset in the 3mf." | none |
| Filament preset incompatible with the machine | 0 | 0 | "Success." | **G-code written**, so farm3d must check this |
| `--slice 2` on a one-plate 3MF | 0 | 0 | "Success." | **no G-code**, so farm3d must check output existence |
| SIGTERM | −15 (signal) | not written | — | none |

## Consequences for the plan

- **P3 presets.** The resolver flattens across vendor bundles by preset
  name. It keeps `from: "system"` and the system names. It checks filament
  `compatible_printers` itself and blocks with `FILAMENT_INCOMPATIBLE`. It
  never passes `--allow-newer-file`. The Open decision decides where presets
  come from for cache-only runtimes.
- **P5 supervision.**
  - Open the FIFO read end (non-blocking) before spawning.
  - Set `PR_SET_PDEATHSIG(SIGTERM)` and `setsid` in `pre_exec`.
  - On cancel, send SIGTERM to the group, allow 5 s, then SIGKILL, and then
    run a stale-mount check. Restart recovery follows the same order.
  - Drop `--mstpp` and use a farm3d wall-clock limit instead.
  - Surface stage messages, because the percentage stalls while loading.
- **Environment.** Spawn OrcaSlicer with an explicit environment that
  drops `DISPLAY`, `WAYLAND_DISPLAY`, `LD_LIBRARY_PATH`, `LD_PRELOAD`,
  `APPDIR`, `APPIMAGE`, `ARGV0`, `OWD`, `GDK_BACKEND`, `GTK_*`, `GIO_*`,
  `GDK_PIXBUF_*`, `GSETTINGS_SCHEMA_DIR`, and `XDG_DATA_DIRS`, and resets
  `PATH` to the system default when farm3d runs as an AppImage (Gate J).
- **Runtime discovery.** Prefer running an AppImage directly (FUSE). Fall
  back to `--appimage-extract-and-run` only when FUSE is unavailable, and
  note its `/tmp` cache.
- **P6 validation.** Map the exit code as the signed `return_code`, and
  prefer `result.json` when it is present. Require `out/plate_1.gcode`,
  since success without output happens. Normalize only line 2 for
  determinism fixtures.
- **P4 plate writer.** Write core 2015/02 with build-item transforms, and no
  Orca metadata. Seeding from an Orca 3MF subtracts the plate's grid origin.
  The stride Orca used here was 300 mm for a 250 mm bed, and the spec must
  pin down the formula from the Orca source.
- **fake-orca (Task 6)** mirrors the observed behaviour:
  - the FIFO line format and the 1 s open retry;
  - the `result.json` shape;
  - the exit codes from the mapping table;
  - success with no output;
  - SIGTERM exit in under 100 ms.
