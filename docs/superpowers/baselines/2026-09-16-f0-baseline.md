The Task 2 security review/controller ruling supersedes the tracer's earlier
design: the
parent owns a temporary config root and passes `XDG_CONFIG_HOME` only to an
isolated child process (`src-tauri/tests/f0_tauri_path.rs:113-136`). The child
marker carries that same temporary config-root path, and child mode is entered
only when the marker equals `XDG_CONFIG_HOME`, so an inherited or pre-existing
marker cannot select the developer's real config. The child
uses a test-owned `127.0.0.1` listener on an ephemeral port that accepts and
immediately closes connections (`src-tauri/tests/f0_tauri_path.rs:23-66` and
`src-tauri/tests/f0_tauri_path.rs:138-180`). It does not use the earlier
reserved-domain endpoint, external DNS, or an authorized live printer. The
empty API key and lazy credential-store detection also avoid the developer's
keychain.

These three Task 1 fixtures are the canonical F0 migration inputs for F1.

Connection save stores a newly submitted secret before persisting its reference
(`src-tauri/src/connections/commands.rs:172-201`), persists Printer state before
starting supervision (`src-tauri/src/connections/commands.rs:193-209`), and
deletes an explicitly cleared old credential before writing the reference-free
Printer config (`src-tauri/src/connections/commands.rs:183-201`). Full
Connection clear immediately aborts supervision, writes the reference-free
Printer, then deletes the deterministic `credential_ref_for(id)` so cleanup
also removes an orphan left by older state; a deletion failure leaves only an
orphaned secret (`src-tauri/src/connections/commands.rs`). Printer deletion
immediately aborts supervision, removes the credential referenced by the stored
Connection, then removes/persists the Printer record
(`src-tauri/src/printers.rs`). Joined shutdown is reserved for tracer teardown
and its `ConnectionManager::stop_and_wait` unit test.

## Defects Discovered During F0

The canonical package recipe did not account for linuxdeploy's bundled legacy
`strip` rejecting modern `.relr.dyn` sections on CachyOS. The original exact
package command is the red reproduction. The AppImage-only `NO_STRIP=1` test
confirmed linuxdeploy's documented bypass, and commit `5952a44` applied it in
`justfile`; the exact package command passed again in the Task 4 final run. No application code or
application-code test was needed.

Before the Task 2 security review, credential-free Connection saves and startup
restoration still called `CredentialStore::detect`, causing an unnecessary
Linux Secret Service round trip that could prompt to unlock a keychain or select
the file fallback even though no credential was needed. The review and
controller ruling supplied the reproduction: save a Connection with no API key,
or start with only reference-free stored Connections, and observe that the
detector was still reached. Production paths are
`src-tauri/src/connections/commands.rs` and `src-tauri/src/lib.rs`; regression
paths are the `credential_free_operation_does_not_detect_a_store` test in
`src-tauri/src/connections/commands.rs` and
`credential_free_startup_does_not_invoke_the_store_detector` in
`src-tauri/src/lib.rs`. The fix detects a store only when a save must read,
write, or delete a credential, or startup sees a stored credential reference.
The tradeoff is a small injected-detector seam; explicit credential-store info
and all credential-bearing paths still perform detection normally.

Task 4 review also found that a pre-existing
`FARM3D_F0_TAURI_PATH_CHILD` marker could make the IPC tracer enter child mode
without its parent-owned temporary config root. The hardened test protocol puts
the temporary root in both the marker and `XDG_CONFIG_HOME` and requires exact
equality. `child_marker_must_match_the_isolated_config_home` in
`src-tauri/tests/f0_tauri_path.rs` covers the stale-marker case. This adds no
production behavior; the tradeoff is only a stricter test-process contract.
